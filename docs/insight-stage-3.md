# Stage 3 — optional local Wellbeing

Schema 6 adds a strictly validated, bounded shared ledger of running timer intervals, completion events and active markers. Existing v0–v5 data migrates without inventing historical duration. The previously unavailable v5 recording preference is reset to off so a new explicit choice is required. Widgets, graph data, assets and layouts are retained.

Timer actions seal actual running intervals on pause/reset/deletion and open new intervals on start/resume. Background reconciliation closes due intervals at their deadlines under the same repository lock and records each work/break completion once. Recording pause/resume omits the gap; clear is separately confirmed. Automatic records and recording controls stay outside user undo, while other widget history remains available. Shared history survives card deletion. Retention, event-count bounds and document-byte capacity are enforced with disclosure of capacity-based removal.

Wellbeing provides Today/7-day/30-day totals, actual work/break running-time charts, an accessible daily table, existing habit check-ins, a user-set break-timer goal and a descriptive focus window only when sufficient retained records exist. No legacy counts are converted to hours, no habit target is invented and no health score is shown. Concurrent timers contribute summed session time, as explained in the page. Back/Escape and focus restoration are preserved.

The four supplied design references guide the new card headers, sage accents, compact graph preview, full canvas with floating tools, four-metric Wellbeing row, paired daily bars, break-goal ring and focus-window panel. Extra recording, privacy and accessible-data controls are available below the main view. Scratchpad editing opens in a drawer. Themes, custom card appearance and narrow layouts remain supported. Visual comparison screenshots contain explicitly isolated sample records, never seeded production activity.

Backups snapshot in-progress recorded time into a copy. Import/restore retains saved records, pauses timers/recording and removes active markers to prevent replay. See [privacy and support](wellbeing-privacy-support.md) for retention/deletion and limitations.

All 122 automated tests passed, as did TypeScript, production build and extension package verification. A capacity check computed correct 30-day totals from 1,000 intervals and 1,000 completions; timings are in `results/wellbeing-capacity-performance.json` (pure computation, excluding browser layout). Verification is recorded in `output/stage-3-tests.log` and `results/wellbeing-stage-3.json`. Browser checks: `scripts/check-wellbeing.mjs`, `scripts/check-wellbeing-extension.mjs`, `scripts/check-idea-canvas.mjs`, `scripts/check-insight-foundation.mjs`. The installed Edge check uses temporary profiles and verifies closed-dashboard alarms, actual browser restarts, offline completion reconciliation and graph persistence. Physical touch, NVDA and real Windows sleep/resume remain manual checks. Notification permission was ungranted in automated installed checks. No website deployment, release ZIP replacement or store submission is included.
